目前架構

後端 API 入口在 server.js
後端圖層資料路由在 layers.js
前端 UI 狀態與底圖互斥邏輯在 App.jsx
地圖渲染核心在 MapViewer.jsx
圖層面板在 LayerControls.jsx
資料流（現在）

使用者在圖層面板切換圖層
App.jsx 更新 layers 狀態（含底圖互斥）
MapViewer.jsx 依 layers 控制 WMTS/OSM/全球衛星與 3D Tiles 顯示
需要向量資料時才走 layers.js（DB 或檔案 fallback）
我看到的重點風險

layers.js 直接把 type 拼進 SQL table 名稱，存在 SQL injection 風險（即使目前有 LAYER_KEYS，但現在是空陣列）。
MapViewer.jsx 已經偏大（渲染、provider 建立、效能策略、互動控制都在同一檔），後續維護成本會上升。
layer-sources.txt 目前混有多段歷史筆記與來源資訊，對維運查找不夠乾淨。
結論

主架構沒有問題，可以持續擴充。
建議優先做兩件事：
鎖定後端 LAYER_KEYS 白名單並移除 SQL 動態拼接風險。
將 MapViewer.jsx 拆成 provider 管理與場景控制模組。
如果你要，我下一步可以直接幫你做第 1 點（後端白名單化，順便補錯誤訊息與測試路徑）。

圖徵點選查詢
點地圖任一設施或圖層要素，右側彈出屬性資訊卡（名稱、類別、來源、時間、連結）。

搜尋與定位
支援地址、地名、座標搜尋，並可一鍵飛到該位置。

圖層透明度滑桿
每個圖層可調透明度，特別適合正射影圖和電子地圖疊比。

量測工具
提供距離、面積、方位角量測，防災與工程情境很常用。

框選查詢與篩選
拉框後只顯示框內資料，並可依屬性篩選（例如只看某縣市、某風險等級）。

時間軸播放
對雨量、地震、即時監測等時間序列資料做回放與快轉。

書籤視角
可儲存多個常用視角（全台、北部、特定案場），一鍵切換。

匯出分享
把目前地圖狀態（中心點、縮放、圖層開關）編碼成分享網址。

圖層載入狀態與錯誤提示
每個圖層顯示 loading/成功/失敗狀態，出錯時提示來源與重試按鈕。

行動版操作優化
手機模式下把圖層面板改為抽屜式，按鈕更大、手勢更直覺。

座標工具列
即時顯示游標經緯度，並可切換顯示 WGS84 與 TWD97。

圖資版本管理
同圖層可切換不同年份或版本，方便比對與回溯。

*優化系統要優先進行 現行優化系統存在誤區 會導致多次加載重複區塊
